# Data4Cyber v3 schema and target-evidence audit

**Audit date:** 31 October 2026
**Release:** [Zenodo v3, DOI 10.5281/zenodo.22953576](https://doi.org/10.5281/zenodo.22953576)
**Status:** source/schema audit only. No detector or XAI result is reported.

## Provenance and coverage

The full 164,148,991-byte archive was downloaded and checked against Zenodo's MD5; all 196 extracted files were written, and all 195 data members listed in `SHA256SUMS.json` match their SHA-256 entries. The 14,354-row attack/benign split tables cover eight scenario folders: 7,586 rows have `attack_active=True` and 6,768 have `attack_active=False`. PCAP members were checksum-verified but not parsed for packet-level semantic validation. The two S1 PV runs are the same attack family and are grouped in any outer evaluation. The Zenodo v3 landing-page summary still lists 5,880 benign and 8,474 attack rows, which are the totals before the S3 label correction described in the archive `CHANGES.md`; the current archive README and SHA-verified split tables report 6,768 benign and 7,586 attack-active rows. The study follows the archive contents and records the stale landing-page metadata as a provenance discrepancy.

## Feature and leakage audit

The process tables place `timestamp`, `attack_active`, `attack_phase`, and `attack_phase_all` next to telemetry. The adapter in `src/xai_cps/data4cyber.py` keeps annotations in separate output fields and excludes them from detector features. It also excludes explicit timestamp/datetime fields and `*.realtime` clock channels. The attack/benign filenames are annotation sources, not model inputs.

The adapter identifies 145 numeric telemetry columns in the attack-family files and preserves missing cells. The archive README reports 7,569 empty feature cells; a direct count on the extracted split CSVs reproduces that number. S4 contributes 4,417 and S6 contributes 1,057 of those cells. `fit_normal_median_imputer` estimates medians only from supplied training-normal rows, drops all-missing training columns, and applies those fixed statistics to calibration/test rows. It is not yet embedded in a full outer-fold benchmark.

## Research-design consequences

1. Use six attack-family outer folds. When S1 is held out, exclude both S1 and S1-alt from training. Keep S0 as normal-only context, and report a sensitivity analysis with and without S0.
2. Fit feature imputation, scaling, detector parameters, thresholds, and any feature grouping on training-normal data only. Calibrate each detector threshold on a separate normal-only subset of non-held-out scenarios.
3. Exclude all activity/phase labels, attack filenames, attack-event logs, PCAP labels, and target maps from fitting, detector scoring, and explanation generation. Use them only after predictions/rankings are frozen.
4. Report explanation localization by evidence tier: (a) exact register-to-process-variable mapping (currently strongest for S3), (b) scenario-documented device group (S4/S5 and potentially S1/S2 as response-group evidence), and (c) coarse asset/phase. Do not combine these tiers into one Hit@K denominator. Mark unresolved targets as unresolved and use explicit denominators.
5. Treat phase overlap and repeated phases in S5 as multi-label. Score first alarms against the full active phase set and separately report exact impact-phase matches. Do not infer causal order from temporal coincidence.
6. The benchmark has one testbed and six attack-family units. Show per-family results; uncertainty from row-level bootstrap is invalid for cross-family generalization. Any family bootstrap or paired test is exploratory and low-powered.

## Outstanding work

The full PCAP pipeline, packet/process synchronization, adjudication of candidate endpoint mappings for S4/S5, per-event target eligibility manifest, and reproduction of the twelve IPAL baselines reported in the dataset paper remain outstanding. The evidence-tiered XAI question is a candidate contribution, not a validated novelty claim. Proceed to explanation experiments only after freezing the mapping/eligibility table and the outer-fold preprocessing protocol.
